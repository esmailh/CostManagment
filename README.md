# مدیریت هزینه

دفترچهٔ هزینهٔ شخصی — کاملاً فارسی، کاملاً آفلاین.

تمام داده‌ها روی خودِ دستگاه ذخیره می‌شوند (IndexedDB) و هیچ سروری در کار نیست. برنامه هم به‌صورت PWA در مرورگر اجرا می‌شود و هم به‌صورت اپلیکیشن اندروید.

---

## امکانات

- **ثبت هزینه** با دسته‌بندی، مبلغ (ریال)، توضیح و تاریخ شمسی
- **تقویم فارسی** درجا‌نشین: شبکهٔ ماهانه، انتخاب ماه، «امروز»، و نام روز هفته کنار تاریخ. همهٔ فیلدهای تاریخ در برنامه از همین یک کامپوننت استفاده می‌کنند
- **هزینه‌های ثابت و تکراری** (اجاره، قسط، قبض) با تولید خودکار هزینهٔ هر ماه
- **وام‌ها**: تعداد اقساط، سررسید ماهانه، مبلغ متفاوت برای قسط‌های خاص، ثبت پرداخت قسط و پیگیری اقساط پرداخت‌شده
- **گزارش‌ها و نمودارها**: تفکیک دسته‌ها، روند ماهانه، مقایسه با ماه قبل
- **مدیریت دسته‌ها و وام‌دهنده‌ها** با آیکون‌های آماده
- **پشتیبان‌گیری و بازگردانی** در قالب فایل JSON (فایل‌های قدیمی نسخهٔ ۱ تا ۳ هم قابل بازگردانی‌اند)
- **تم روشن و تاریک**، با پیروی از تنظیم سیستم
- **راه‌اندازی اولیه** برای وارد کردن اولین دسته‌ها

## پشتهٔ فنی

| بخش | ابزار |
| --- | --- |
| رابط کاربری | React 18 + TypeScript 5 |
| بیلد | Vite 5 |
| ذخیره‌سازی | IndexedDB با Dexie 4 |
| تقویم شمسی | `jalaali-js` |
| اپلیکیشن اندروید | Capacitor 6 |
| PWA | `vite-plugin-pwa` (با به‌روزرسانی خودکار و کار آفلاین) |
| فونت | Vazirmatn |

شناسهٔ اندروید: `com.personal.expensetracker`

## ساخت و انتشار

### وب (PWA)

```bash
npm run build     # خروجی در dist/
npm run preview   # نمایش خروجی ساخته‌شده
```

### فایل تک‌پارچه (برای باز کردن از حافظهٔ گوشی)

```bash
npm run build:single   # خروجی در dist-single/index.html
```

### اپلیکیشن اندروید

```bash
npm run android:sync
cd android && ./gradlew.bat assembleDebug
```

خروجی: `android/app/build/outputs/apk/debug/app-debug.apk`

> **نکته:** `npm run android:debug` روی ویندوز کامل اجرا نمی‌شود. اسکریپت درست نوشته شده، اما npm آن را در cmd اجرا می‌کند و `gradlew.bat` را از پوشهٔ جاری پیدا نمی‌کند؛ بعد از موفقیت بیلد وب و `cap sync` با پیام `'gradlew.bat' is not recognized` می‌میرد. دو نیمه را جدا اجرا کنید (همان دو دستور بالا).

> **نکته:** `npm run build:single` فایل `expense-tracker.html` در ریشهٔ پروژه را به‌روز نمی‌کند؛ آن یک نسخهٔ دستی‌کپی‌شده است. اگر از آن استفاده می‌کنید، خودتان از `dist-single/index.html` کپی بگیرید.

بعد از هر تغییر در رابط کاربری، پیشنهاد می‌شود مطمئن شوید بیلد تازه واقعاً به دست دستگاه رسیده — نام فایل هش‌دار باندل (`dist/assets/index-*.js`) را با همان فایل داخل APK مقایسه کنید.

## ساختار پروژه

```
src/
  components/     کامپوننت‌های مشترک (فرم هزینه، تقویم شمسی، پوسته، آیکون‌ها)
    charts/       نمودارهای میله‌ای، فهرستی و دونات
    ui/           دکمه، مودال، شیت، فیلد، دیالوگ تأیید
  pages/          صفحه‌های اصلی (داشبورد، هزینه‌ها، وام‌ها، گزارش‌ها، تنظیمات)
    settings/     مدیریت دسته‌ها، وام‌دهنده‌ها، هزینه‌های ثابت، پشتیبان‌گیری
  services/       منطق کار با داده (هزینه‌ها، وام‌ها، گزارش‌ها، پشتیبان)
  db/             تعریف دیتابیس Dexie و مهاجرت‌های نسخه‌ها
  hooks/          هوک‌های React برای خواندن داده
  lib/            توابع کمکی (تاریخ شمسی، قالب‌بندی، آیکون‌ها)
  styles/         استایل‌های سراسری و متغیرهای تم
```

## داده‌ها و حریم خصوصی

- هیچ داده‌ای از دستگاه بیرون نمی‌رود. نه حساب کاربری، نه سرور، نه تحلیل بازدید.
- تنها راه انتقال داده، **پشتیبان‌گیری JSON** از بخش تنظیمات است.
- پوشهٔ `android/phone-backups/` در `.gitignore` است: این پوشه دامپ خام دیتابیس واقعی روی گوشی است و **نباید commit شود**. به همین دلیل `apk/*.apk` و `expense-tracker.html` هم — که خروجی بیلد هستند و دستی کپی می‌شوند — در مخزن نگه داشته نمی‌شوند.

## نکته‌های پیاده‌سازی

- همهٔ محاسبات تاریخ از `src/lib/jalaali.ts` می‌آید؛ هیچ‌جای برنامه از تاریخ میلادی یا `<input type="date">` استفاده نمی‌شود.
- مبالغ به **ریال** ذخیره و نمایش داده می‌شوند.
- رابط کاربری راست‌به‌چپ است؛ در چیدمان‌های RTL اولین فرزند DOM سمت راست می‌نشیند، بنابراین آیکون‌های ماه قبل/بعد بر همین اساس چیده شده‌اند.
- دو اسکریپت `scripts/smoke-data.mjs` و `scripts/test-file.mjs` هارنس‌های محلی هستند و مسیرهای مطلق همین دستگاه در آن‌ها ثابت شده است؛ برای اجرا باید مسیرها را برای سیستم خودتان تغییر دهید.
